### 🎯 Goal
Bring `--warning`, `--success` and `--destructive` up to the 4.5:1 contrast bar the design system's
own accessibility law sets, so they can safely be used as text.

### 🧭 Slice Strategy
- [ ] ↕️ Vertical — thin end-to-end increment, demoable on merge
- [ ] ↔️ Horizontal — single architectural layer
- [x] 🐛 Ad-hoc — bug · edge-case · tech-debt · security

### 🏷️ Classification
`bug` / `accessibility`

### 📁 Affected Files
- `src/app/globals.css`
- `DESIGN.md`

### 🔎 What happened
`/frontend-audit` computes 11 WCAG failures across the status tokens in both themes. The worst cases:

| Pair | Mode | Ratio | Bar |
|---|---|---|---|
| `--warning` on `--muted` | light | **2.78:1** | 4.5:1 |
| `--warning` on `--background` | light | **3.17:1** | 4.5:1 |
| `--warning` on `--card` / `--popover` | light | **3.31:1** | 4.5:1 |
| `--destructive` on `--card` / `--popover` | dark | **3.49:1** | 4.5:1 |
| `--destructive` on `--muted` | dark | **3.21:1** | 4.5:1 |
| `--success` on `--muted` | light | **3.86:1** | 4.5:1 |
| `--success` on `--background` | light | **4.40:1** | 4.5:1 |

### ✅ Expected vs ❌ Actual
- **Expected:** any status token usable as a text colour meets 4.5:1 on the surfaces it sits on, as
  `DESIGN.md` requires.
- **Actual:** all three status colours fail on at least one standard surface; `--warning` fails on
  every surface in light mode.

### 🔁 Reproduction
```bash
python <playbook>/commands/frontend-audit/audit.py DESIGN.md src/app/globals.css
# => laws: contrast:FAIL ... 11 error
```

### 🧠 Suspected cause
The palette shades were chosen for *recognisability* (an amber that reads as amber, a green that
reads as green) rather than for contrast as text. This is the classic drift the audit's Law 7b
describes: a value picked so a dot reads correctly, then reused as a label.

### 🩹 Current mitigation (not a fix)
`src/components/ui/badge.tsx` renders status **text** in `--foreground` and uses the status colour
only for a 1px border — a graphic element, held to the 3:1 bar, which these values do pass. So no
shipped screen currently uses a status colour as text. The tokens remain a trap for the next
component that does.

### 🛠️ Implementation Tasks
- [ ] Darken `--warning` / `--success` in light mode and lighten `--destructive` in dark mode until
      every pair clears 4.5:1; re-run the audit after each change rather than eyeballing.
- [ ] If a token is genuinely only ever a dot or a bar, rename it (`--warning-dot`) or mark it
      `/* decorative */` instead of forcing the ratio — but decide deliberately, per token.
- [ ] Update the token table in `DESIGN.md` so the spec and the stylesheet agree.
- [ ] Re-run `/frontend-audit` across `DESIGN.md` + `src/` and confirm `contrast:ok`.
