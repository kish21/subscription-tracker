### 🔌 Contract — Inputs → Outputs
- **Consumes:** `RATE_LIMIT_ENABLED`, `RATE_LIMIT_WINDOW_SECONDS`, `RATE_LIMIT_SIGNUP_MAX`, `RATE_LIMIT_LOGIN_MAX`, `ERROR_REPORTER`, `SENTRY_DSN`, `ERROR_REPORTER_TIMEOUT_MS` — all already reserved in `.env.example`
- **Exposes:** `429` with a `Retry-After` header past the threshold; a config-selected `ErrorReporter` implementation behind the existing interface

### 🔗 Depends On
`[M3-SLICE-01]` — thresholds and the DSN are only meaningful once there is a deployed environment to set them in.

### 👀 Demo — what works after this merges
A scripted burst of login attempts against the live URL returns `200`/`401` up to the configured maximum and `429` with `Retry-After` after it, and the limit holds across restarts because it is DB-backed. A deliberately triggered server error appears in the Sentry project within seconds, while the user request itself still completes.

### 🛠️ Implementation Tasks
- [ ] Enable Better Auth's DB-backed rate limiter in `src/auth/server.ts`, reading every threshold from config — **no literal numbers in source**.
- [ ] Replace `SentryStubErrorReporter` in `src/providers/error-reporter.ts` with a real adapter, still behind the existing `ErrorReporter` interface and still selected by `ERROR_REPORTER`.
- [ ] Keep `capture()` fire-and-forget with the configured timeout: a reporting failure must never fail a user request.
- [ ] Promote the commented-out `RATE_LIMIT_*` and `ERROR_REPORTER` keys in `.env.example` to documented, active entries.
- [ ] Write `tests/integration/rate-limit.test.ts` proving the threshold triggers, `Retry-After` is present, and the counter survives a process restart.
- [ ] Write feature documentation in `docs/features/production-hardening.md`.

### 🔒 Security in the Definition of Done
- [x] Rate limiting fails **closed** — if the limiter's backing store errors, the request is rejected, not waved through.
- [x] The `429` response is generic; it must not reveal whether the account exists.
- [x] No DSN, key or threshold hardcoded — all from `.env`, validated at boot, documented in `.env.example`.
- [x] The reporter never transmits subscription content, prices or passwords; PII scrubbing verified by a test.
- [x] No swallowed errors; the vendor SDK is imported **only** inside the adapter, never in a service or component.
