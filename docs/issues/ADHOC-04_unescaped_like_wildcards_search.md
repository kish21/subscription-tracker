### 🐛 Defect Description
- **What happened:** In `DrizzleSubscriptionRepository.list`, the search clause uses `ilike(subscriptions.name, `%${filter.search}%`)`. Because the input string is not sanitized for SQL wildcard characters, characters like `%` (match zero or more characters) and `_` (match exactly one character) alter the search semantics.
- **Expected:** Searching for `100%` should match subscriptions named `100% Cotton`, but not subscriptions named `1000 Subscribers`. Searching for `_` should match names containing an underscore (like `dev_tools`), not all subscriptions.
- **Actual:** User-supplied `%` and `_` are treated as SQL wildcards.
- **Trigger condition:** Querying `GET /api/v1/subscriptions?search=_` or `GET /api/v1/subscriptions?search=%`.

### 🛠️ Implementation Tasks
- [x] Implement `escapeLikePattern(str: string): string` helper escaping `\`, `%`, and `_`.
- [x] Use `escapeLikePattern` in `DrizzleSubscriptionRepository.list` when constructing the search filter.
- [x] Add unit/integration test in `tests/integration/subscriptions.test.ts` verifying literal search for names containing `%` and `_`.
