### 🎯 Goal
Ship the app to a public HTTPS URL from a host-agnostic container (ADR-007), with migrations run as an explicit start-path step and every secret supplied by the host's environment — never baked into the image.

### 🔌 Contract — Inputs → Outputs
- **Consumes:** the Zod-validated env schema in `src/config/loader.ts` (`DATABASE_URL`, `BETTER_AUTH_SECRET`, `APP_ORIGIN`), supplied by the host's environment
- **Exposes:** a running container on a public HTTPS origin; `GET /api/health` returns 200 with the schema migrated

### 🔗 Depends On
`[M1-SLICE-03]`, `[M2-SLICE-01]`, `[M2-SLICE-02]` — the full in-scope surface must exist before it is worth deploying.

### 👀 Demo — what works after this merges
A fresh browser (no local setup, no cookies) opens the public HTTPS URL, signs up, adds a subscription, logs out, logs back in, and still sees it. `GET /api/health` returns 200 from that same URL.

### 🛠️ Implementation Tasks
- [ ] Write a multi-stage `Dockerfile` (Node 22, pnpm, Next standalone output) — no host-proprietary runtime APIs, per ADR-007.
- [ ] Write `scripts/start.sh`: run `drizzle-kit migrate`, then start the server. Migration failure must abort the boot, never start a server against an unmigrated DB.
- [ ] Choose the deploy target and record it as **ADR-008** in `PRODUCT.md#Architecture` (deliberately deferred to M3 by ADR-007).
- [ ] Add `.github/workflows/deploy.yml` building and publishing the image on a green `main`.
- [ ] Set `APP_ORIGIN` to the public origin so the session cookie is `Secure` + `SameSite=Lax` and CORS is locked to it.
- [ ] Write `tests/e2e/m3-production-smoke.test.ts` running the signup → add → logout → login journey against a configurable base URL.
- [ ] Write feature documentation in `docs/features/deployment.md`.

### 🔒 Security in the Definition of Done
- [x] No secret is present in the image, the repo or the workflow file — all injected from the host env; gitleaks clean.
- [x] HTTPS only; session cookie `httpOnly` + `Secure` + `SameSite=Lax` verified on the live origin.
- [x] `db push` is never run against the deployed database (ADR-003); schema changes only via checked-in SQL.
- [x] Boot fails loud and closed on a missing or malformed env var, rather than defaulting silently.
- [x] No stray prints; structured logging only.

### 🧪 Verification Plan
- **Automated tests:** `pnpm test:e2e tests/e2e/m3-production-smoke.test.ts` against the deployed URL.
- **Manual demo path:** `curl -I https://<public-url>/api/health` → `200`; inspect the `Set-Cookie` header on login for `Secure; HttpOnly; SameSite=Lax`.
