### 🐛 Defect Description
- **What happened:** In `DrizzleSubscriptionRepository.create`, the method performs `findByIdempotencyKey` prior to inserting. If two identical requests execute concurrently before either has committed, both queries find `null`. The first `insert` succeeds, while the second insert throws a PostgreSQL error `23505` on `subscriptions_user_idempotency_idx`.
- **Expected:** Concurrent requests with identical idempotency keys should both resolve to the created subscription (HTTP 200/201), rather than failing with an unhandled 500 error.
- **Actual:** The second request throws `error: duplicate key value violates unique constraint "subscriptions_user_idempotency_idx"`, propagating an unhandled 500 error to the client.
- **Trigger condition:** Rapid double submission of the same subscription creation payload or network retry with the same `idempotencyKey`.

### 🛠️ Implementation Tasks
- [x] Update `DrizzleSubscriptionRepository.create` to catch PostgreSQL error code `23505` (unique constraint violation) on `subscriptions_user_idempotency_idx`.
- [x] On catching `23505`, re-query and return `findByIdempotencyKey(userId, input.idempotencyKey)`.
- [x] Add concurrent integration test in `tests/integration/subscriptions.test.ts` executing `Promise.all([create, create])` with identical `idempotencyKey` and verify both promises resolve to the same subscription record.
