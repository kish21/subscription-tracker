### 🎯 Goal
Let a user delete their account and take all of their data with them — every subscription and session row gone, verifiable by a direct DB query — so the privacy promise in the Vision holds at the exit as well as the entrance.

### 🔌 Contract — Inputs → Outputs
- **Consumes:** `DeleteAccountInputSchema` (new, in `src/schemas/auth.ts`) — requires re-entry of the current password as confirmation; the authenticated `userId` from `SessionReader`
- **Exposes:** `DELETE /api/v1/account` → `{ success: true }` and a cleared session cookie; `UserRepository.deleteAccount(userId)`

### 🔗 Depends On
`[M1-SLICE-01]`, `[M1-SLICE-02]` — needs the session guard and the subscriptions table.

### 👀 Demo — what works after this merges
A logged-in user opens Settings, clicks "Delete my account", re-enters their password, confirms, and is signed out to the landing page. A DB query for that `user_id` returns zero rows in `subscriptions`, `session` and `user`. Logging in with the old credentials fails.

### 🛠️ Implementation Tasks
- [ ] Add `DeleteAccountInputSchema` (password confirmation) to `src/schemas/auth.ts`.
- [ ] Add `deleteAccount(userId)` to a new `src/db/repositories/user.ts`, deleting inside a single transaction and relying on the existing cascading FKs declared in `src/db/schema/index.ts`.
- [ ] Implement `DELETE /api/v1/account` — verify session, re-verify password via Better Auth, delete, then revoke the session cookie.
- [ ] Build `DeleteAccountDialog` with a typed-confirmation destructive pattern, using `DESIGN.md` tokens.
- [ ] Add a Settings page at `src/app/dashboard/settings/page.tsx` hosting the dialog.
- [ ] Write `tests/integration/account-deletion.test.ts`: deletion removes all rows; **User B cannot delete User A's account**; a wrong password fails closed.
- [ ] Write feature documentation in `docs/features/account-deletion.md`.

### 🔒 Security in the Definition of Done
- [x] Re-authentication (password re-entry) required before deletion — a stolen session alone cannot destroy an account.
- [x] Deletion is scoped to the session's own `userId`; there is no route that accepts a target user id (ADR-005).
- [x] Adversarial test proves User B cannot delete User A's account.
- [x] Cascade verified by a real DB query, not assumed from the schema declaration.
- [x] Session revoked server-side on success; no orphaned rows, no swallowed errors.

### 🧪 Verification Plan
- **Automated tests:** `pnpm test:integration tests/integration/account-deletion.test.ts`
- **Manual demo path:** delete the account, then `psql -c "SELECT count(*) FROM subscriptions WHERE user_id='<id>'"` → `0`, and confirm login with the old credentials is rejected.
